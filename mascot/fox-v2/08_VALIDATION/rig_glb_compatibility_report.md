## 2. Face system: visibility swaps → morph targets

Problem in D1: the face used `hide_viewport` / `hide_render` driven by the `FACE` bone (42 drivers). glTF **does not export visibility animation or drivers**, so in an engine the face parts would either all show at once or never change.

The D1.1 solution uses **only glTF morph targets** (`weights` animation channels):

| Group | Parts | Mechanism |
|---|---|---|
| Visible by default | `FOX_Eye_L/R`, `FOX_Mouth_Neutral` | Real basis. Morph `hide` collapses the part to a point inside the surface |
| Swap parts (11) | EyeClosedHappy L/R, EyeClosedSleepy L/R, Mouth Open/Tongue/SmallO/Frown/Smile, Brow L/R | The basis is collapsed (invisible at rest). Morph `show` restores the real shape |
| Shape morphs | Eye: `Blink`, `Wide`, `Sad`, `HalfLid`, `Proud` · Brow: `Sad`, `Proud` (complete alternatives used **instead of** `show`) | Normal shape keys |

Expression = set of morph weights (see `face_morph_map.json` → `expressions`):

- neutral: everything 0
- blink: Eye Blink 1
- happy: Eye hide, EyeClosedHappy show, Mouth_Neutral hide, Mouth_Open + Tongue show
- proud: Eye Proud, Brow Proud, Mouth_Smile show
- sad: Eye Sad, Brow Sad, Mouth_Frown show
- surprised: Eye Wide, Mouth_SmallO show
- sleepy: Eye hide, EyeClosedSleepy show, Mouth_SmallO show

Collapsed parts are 0-area triangles inside the head, so nothing shows. The app/engine changes expression by setting `mesh.morphTargetInfluences[...]`, the same way the viewer does. Blink in the clips is a `weights` animation.

Note for runtime: Three.js computes the bounding sphere from the basis. A collapsed swap part therefore needs **`frustumCulled = false`** (the viewer already sets this), otherwise it can be culled when shown.

## 3. Export settings

- Blender 5.3, `export_scene.gltf`: GLB, `export_apply`, animation mode ACTIONS, morph + morph normals + morph animation, skins on, `export_def_bones=False`. Lights and cameras are not exported.
- **LOD:** base cage (subdivision 0). The scarf roll and bandana are at level 1 because at level 0 they look crumpled. Result: ~73.8k tris, which is the D1.1 test level. Gate F will build the official mobile LODs.
- **Face decal refit:** decals were placed on the level-2 head. At level 0 the head surface sits slightly lower, so each decal is re-projected onto the export surface. The largest offset is 0.64 mm (mouth), with no z-fighting and no floating.
- **Duplicate materials:** the master has 12 `.00N` slots created by module appends. At export they are remapped in memory to the base material, so the GLB has exactly 12 materials. *The master is unchanged; the duplicates will be cleaned up in Gate F.*
- Extensions: `KHR_materials_clearcoat`, `KHR_materials_specular`, `KHR_materials_sheen`. Three.js supports all of them, and engines that do not will fall back to base colour.
- Draco and meshopt compression are not used (the encoder is not available in the build environment). Size is 2.09 MB uncompressed.

## 5. How to run

```
python3 08_VALIDATION/scripts/export_glb_d1_1.py      # GLB + manifest
python3 08_VALIDATION/scripts/make_rig_viewer.py      # 07_WEB_PREVIEW/rig_test.html
python3 08_VALIDATION/scripts/browser_rig_test.py     # Playwright + Chrome, writes runtime/
```

To view manually: serve the project root over HTTP (for example `python3 -m http.server` at the project root) and open `/07_WEB_PREVIEW/rig_test.html`. If you open it via `file://`, drag and drop the GLB into the page. In the browser console, `window.runChecks()` re-runs the 15 checks.
